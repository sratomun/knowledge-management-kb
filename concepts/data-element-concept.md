# Data element concept

## What it is
A data element concept (DEC) is the representation-independent idea behind a data element: a concept (such as "income") bound to an object class (such as "person"), describing *what* is being recorded without committing to *how* the value is represented. One data element concept can be realized by several concrete data elements that differ only in representation.

## How sources treat it
- **[[iso-iec-11179-1]]** _(standard · normative)_ — When applied to data modelling, the standard combines a wide "concept" with an "object class" to form a more specific "data element concept" — e.g. the concept "income" plus the object class "person" gives the data element concept "net income of person" ⟨Wikipedia: ISO/IEC 11179⟩.
- **[[iso-iec-11179-1]]** _(standard · normative)_ — The different possible representations of a data element concept are described using one or more data elements; differences in representation may result from synonyms or different value domains across data sets ⟨Wikipedia: ISO/IEC 11179⟩.
- **[[iso-iec-11179-1]]** _(standard · normative)_ — The core object of the standard is the data element concept, since it defines a concept and, ideally, describes data independent of its representation in any one system, table, column, or organisation ⟨Wikipedia: ISO/IEC 11179⟩.
- **[[iso-iec-11179-1]]** _(standard · normative)_ — The model derives partly from the semantic-theory distinction between a concept and its representation (e.g. "buy" and "purchase" are the same concept with different terms) ⟨Wikipedia: ISO/IEC 11179⟩.

## Where sources differ
Only ISO/IEC 11179 is sourced for this concept, so there is no cross-source divergence to report. The points here come from secondary sources (the Wikipedia article and the ISO abstract) because the primary standard text is paywalled ⟨Wikipedia: ISO/IEC 11179⟩.
