# Architecture Domains

## What it is

Architecture domains are the distinct but related subject areas into which enterprise-architecture work is divided so that each can be described and governed with appropriate concern-specific views — commonly business, data, application, and technology. The domains partition an otherwise sprawling architecture into layers that different specialists own while still fitting together into one enterprise architecture.

## How sources treat it

- **[[togaf]]** _(standard · normative)_ — TOGAF organizes architecture work into four architecture domains: Business, Data, Application, and Technology architecture, with Data and Application together forming the Information Systems Architectures ⟨TOGAF⟩ [gen]
- **[[togaf]]** _(standard · normative)_ — The ADM's phases map onto these domains — B Business Architecture, C Information Systems Architectures (Data and Application), and D Technology Architecture ⟨TOGAF⟩ [gen]
- **[[togaf]]** _(standard · normative)_ — The Architecture Content Framework and Content Metamodel describe the architectural artifacts, deliverables, and building blocks produced across the domains ⟨TOGAF⟩ [gen]

## Where sources differ

Only the TOGAF Standard is cited here, and the four-domain scheme is marked [gen] in the source — drawn from general knowledge because the full normative text was not consulted, with only the public overview page directly cited. No competing partitioning is recorded in the corpus.
