# Data Management Capability Model

## What it is

A data management capability model is a structured reference that decomposes the practice of managing data into a set of named capabilities (and sub-capabilities), each with objectives and evaluation criteria, so that an organization can describe what a data program should be able to do and assess how well it does it. It is descriptive best practice rather than a regulation or a single prescribed implementation: the model enumerates capabilities and lets an organization measure, benchmark, and plan improvements against them.

## How sources treat it

- **[[edm-dcam]]** _(whitepaper · informational)_ — Organized into eight key components spanning the data supply chain, from establishing a data management foundation through managing advanced analytics ⟨edmcouncil.org/dcam⟩
- **[[edm-dcam]]** _(whitepaper · informational)_ — DCAM v3 is constructed as 34 required data management capabilities decomposed into 101 sub-capabilities, each expressed through objectives, questions, artifacts of evidence, and criteria for scoring ⟨edmcouncil.org/dcam⟩
- **[[edm-dcam]]** _(whitepaper · informational)_ — v3 enhances the components with an integrated Architecture component and a new Business Data Knowledge component, and adds expanded support for AI/ML integration, cloud-native architectures, and modern data pipelines ⟨edmcouncil.org/dcam⟩
- **[[edm-dcam]]** _(whitepaper · informational)_ — [gen] As a capability assessment model it measures the maturity of capabilities rather than prescribing a single implementation, positioning data governance as a central, cross-cutting capability ⟨DCAM⟩
- **[[edm-dcam]]** _(whitepaper · informational)_ — [gen] Earlier public DCAM materials framed the model around components such as Data Management Strategy, Business Case & Funding, Data Governance, Data Architecture, Technology Architecture, Data Quality, and Data Operations ⟨DCAM⟩

## Where sources differ

Only the EDM DCAM source is cited here. Its account carries an explicit honesty caveat: the full DCAM framework is members-only and was not consulted, so the key points come from the public overview page plus general knowledge (marked [gen]) rather than from the licensed specification. The source positions DCAM as a descriptive best-practices reference rather than a prescriptive standard.
