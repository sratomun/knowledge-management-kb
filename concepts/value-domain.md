# Value domain

## What it is
A value domain is the permitted set or range of values that a data element may take — the representation-level "what values are allowed here," such as an enumerated code list or a numeric range. It is the representation counterpart to a conceptual domain: the same underlying meanings can be carried by different value domains.

## How sources treat it
- **[[iso-iec-11179-1]]** _(standard · normative)_ — A value domain is the permitted range of values for a characteristic of an object class; e.g. a value domain for "sex of person" is "M = Male, F = Female, U = Unknown," where M, F and U are the permitted values in a particular data set ⟨Wikipedia: ISO/IEC 11179⟩.
- **[[iso-iec-11179-1]]** _(standard · normative)_ — Differences in the representation of a data element concept may result from the use of synonyms or different value domains across data sets in a data holding ⟨Wikipedia: ISO/IEC 11179⟩.
- **[[iso-iec-11179-1]]** _(standard · normative)_ — Data elements storing codes or enumerated values must specify the semantics of each code value with a precise definition ⟨Wikipedia: ISO/IEC 11179⟩.

## Where sources differ
Only ISO/IEC 11179 is sourced for this concept, so there is no cross-source divergence to report. The points here derive from secondary sources (the Wikipedia article and the ISO abstract), as the primary text is paywalled ⟨Wikipedia: ISO/IEC 11179⟩. Within 11179, note the value domain (representation-level permitted values) is kept distinct from the conceptual domain (representation-independent value meanings).
